# Dataverse Data Model

## Scope and provenance

This first implementation slice provisions the 17 tables defined in the approved plan into the
unmanaged `SRMAgentDemo` solution in DemoPRE. The live tables use the dedicated `mag` publisher.
Each table has a `mag_DemoKey` alternate key so the sample import can be safely rerun.

The model realizes the core review workflow, its mock external systems, configurable rule tables,
and the Supplier One-Page Summary. It does not create the BPF, model-driven app, agent actions,
security roles, or external connections.

## Key design decisions

- All custom table and column schemas use the permanent `mag` publisher prefix.
- Each entity includes a stable `DemoKey`; an alternate key on `mag_demokey` enables repeatable
  seed imports without duplicate rows.
- Relationship fields are lookups, not string IDs. CSV fixtures refer to parent records by their
  `DemoKey`, which the importer resolves to Dataverse record IDs.
- The Early Warning and review-request association is bidirectional. The seed importer first creates
  warning rows, then requests referencing warnings, and finally updates warnings with the request
  lookup.
- The supplier document table has a Dataverse file column. Fictional seed rows carry document names
  and metadata only; no binary or real supplier document is embedded.
- All GSA, Coface, D&B, eRFX, adverse-event, supplier, and financial data is synthetic. `example.invalid`
  URLs are placeholders and are not fetched.
- The Coface conversion and financial-risk thresholds in the seed set are explicitly `Draft - demo
  only`. The source material does not define approved scoring bands. These rows must not be treated
  as MAGNA policy.
- AI/preliminary ratings are stored separately from final ratings. Only the GSA reuse branch has a
  final rating seeded as completed; all other outcomes remain reviewer-confirmable.
- The One-Page Summary is seeded only for suppliers with active spend.

## Seed scenario coverage

The 12 fictional supplier records exercise the planned branches:

| Scenario | Records | Expected outcome |
|---|---:|---|
| Active GSA rating, no mandatory re-review | 3 | Auto-completed GSA reuse |
| Expired GSA rating | 2 | Full review |
| Valid GSA rating with mandatory re-review | 2 | Full review |
| No GSA match with recent Coface data | 2 | Coface fast-track to reviewer decision |
| No DUNS and multiple fuzzy Coface candidates | 2 | Full review; no authoritative Coface match |
| Distressed supplier with stale Coface data | 1 | Full review, deteriorating multi-year working paper, non-financial risks, and open high-materiality Early Warning |

## Provision and import

1. Confirm `DATAVERSE_URL` and `TENANT_ID` are configured for the target environment and that the
   user is authenticated with the required customization privileges.
2. Run `python scripts/02-create-tables.py` to create all tables, lookups, and alternate keys in
   `SRMAgentDemo`. Metadata operations are phased and retry transient customization locks.
3. Run `python scripts/03-import-sampledata.py` to write the fictional CSV fixtures and idempotently
   upsert them in dependency order.
4. Run `python scripts/verify-datamodel.py` to validate table columns, solution membership, seeded
   keys/counts, and review-path coverage in DemoPRE.
5. After verification succeeds, export and unpack `SRMAgentDemo` into `solutions/SRMAgentDemo/` if
   the local source does not already represent the deployed metadata. Follow the Solution Source
   Synchronization procedure in [`AGENTS.md`](../AGENTS.md#solution-source-synchronization).

The scripts use the Dataverse SDK's shared `auth.py` helper. In an initialized Dataverse skills
workspace, make it importable (for example, by running with the skills `scripts` directory on
`PYTHONPATH`). Never commit `.env`, credentials, tokens, or environment-specific secrets.

## Deferred follow-up

The model does not yet create the 5-stage BPF or the app forms/views, security roles, flows, actual
Copilot Studio actions, scheduled adverse-news ingestion, or binary archive documents. Those remain
separate implementation-plan items.
